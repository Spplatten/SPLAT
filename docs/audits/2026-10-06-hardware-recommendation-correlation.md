This is source analysis and inspection of recorded evidence; no performance benchmark or privileged probe was executed for this review. Runtime code is unchanged.

**Recommendation:** retain the C/eBPF enforcement, Rust/libbpf consumption, and authenticated C# bridge. Prefer bounded, typed binary decoding with a small, documented unsafe boundary. Investigate allocation, logging, event routing, and overload handling before introducing compiler tricks. Their performance impact remains a hypothesis until measured.

The ring is a **multiple-producer, single-consumer** design: hooks can execute concurrently on different CPUs. It is an evidence channel, not the mechanism that decides whether an operation is permitted. Failed event reservation increments a drop counter while the hook still denies the operation. [Kernel ring-buffer design](https://docs.kernel.org/bpf/ringbuf.html), [SPLAT reporting](C:/C_AGENT_BUILDER/native/splat-agent/src/bpf/lease_lsm.bpf.c:182).

| Supplied technique | Correlation and recommendation |
| --- | --- |
| Protothreads | **Do not introduce them here.** The daemon already uses Tokio async tasks. Protothreads address a different constraint: their two-byte figure describes continuation state, not all application state, and ordinary local variables do not survive a yield. They do not make pointer parsing safer or preserve the post-fork safety contract automatically. [Daemon tasks](C:/C_AGENT_BUILDER/native/splat-agent/src/main.rs:550), [author's description](https://dunkels.com/adam/pt/about.html). |
| Replace logical operators with bitwise operators | **Reject blanket replacement.** `scratch_dev && *scratch_dev == k.dev` deliberately avoids dereferencing a null map result. Removing short-circuit evaluation can destroy the safety condition. Bitwise combination is suitable for independent, already-valid scalar flags, but guarantees neither branchless machine code nor verifier acceptance. The verifier uses branches to establish pointer validity and bounds. [Existing guard](C:/C_AGENT_BUILDER/native/splat-agent/src/bpf/lease_lsm.bpf.c:277), [verifier rules](https://docs.kernel.org/bpf/verifier.html). |
| `likely()` / `unlikely()` | **Measure before adding.** The hooks already return early for unleased cgroups and prior denials. A branch hint communicates an expectation to the compiler; it does not force CPU prediction, cache placement, or a particular final instruction sequence. Compare generated BPF and JIT code on the supported kernel. [Current fast path](C:/C_AGENT_BUILDER/native/splat-agent/src/bpf/lease_lsm.bpf.c:249), [compiler semantics](https://gcc.gnu.org/onlinedocs/gcc/Other-Builtins.html). |
| Forced inlining and loop unrolling | **Inlining is already present; blanket unrolling has no current target.** The BPF helpers use `__always_inline`, and these hooks contain no C loops. The build already uses Clang `-O2 -mcpu=v3`. Inlining can increase code size and register pressure; it does not guarantee reduced stack use. Acceptance must be established by loading the resulting program, not inferred from the annotation. [Helpers](C:/C_AGENT_BUILDER/native/splat-agent/src/bpf/lease_lsm.bpf.c:177), [build flags](C:/C_AGENT_BUILDER/native/splat-agent/build.rs:11), [verifier limits](https://docs.kernel.org/bpf/bpf_design_QA.html#q-what-are-the-verifier-limits). |
| Cache-aligned custom SPSC ring | **Keep the kernel ring.** Treating the whole kernel as one producer is incorrect. The kernel implementation already separates consumer and producer positions into different pages. The supplied SPSC sketch also lacks complete capacity, payload-length, and consumer synchronization handling. A separate SPSC queue could be evaluated between exactly one Rust drain thread and one dispatcher, but would not replace the kernel ring. [Kernel layout](https://raw.githubusercontent.com/torvalds/linux/master/kernel/bpf/ringbuf.c), [current map](C:/C_AGENT_BUILDER/native/splat-agent/src/bpf/lease_lsm.bpf.c:153). |
| Acquire/release atomics | **Correct principle; incorrect physical explanation.** Release/acquire establishes visibility and ordering when the acquire observes the release. It does not flush all writes to DRAM. Sequential consistency is not synonymous with locking a hardware bus. Kernel/libbpf already implement the ring protocol; do not replace it with two application atomics. [Atomic semantics](https://gcc.gnu.org/onlinedocs/gcc/_005f_005fatomic-Builtins.html), [libbpf implementation](https://raw.githubusercontent.com/libbpf/libbpf/v1.7.0/src/ringbuf.c). |
| Zero-copy kernel-to-user delivery | **Already used at the BPF-to-Rust boundary.** `reserve`/`submit` writes directly into the mapped ring, and the callback reads the record in place. The complete route is not zero-allocation: Rust creates strings and JSON, and C# parses JSON. Polling also uses system calls. Direct Windows C# pointers cannot expose memory in the WSL guest without a different transport and ownership contract. [Reservation API](https://docs.kernel.org/bpf/ringbuf.html), [current callback](C:/C_AGENT_BUILDER/native/splat-agent/src/main.rs:365). |
| Packed structs and reclaimed padding | **Keep explicit ABI layouts.** The event is 52 bytes of fields, padded to 56. Packing it to 52 would still occupy 64 bytes in the ring: `round_up(payload + 8-byte header, 8)` gives 64 for both. There is no ring-capacity gain from that change. Use named, initialized, versioned fields for flags. Do not hide state in map-key padding: changing those bytes changes the key. [Event layout](C:/C_AGENT_BUILDER/native/splat-agent/src/violation.rs:18), [map-key padding](C:/C_AGENT_BUILDER/native/splat-agent/src/lease.rs:33), [record rounding](https://raw.githubusercontent.com/libbpf/libbpf/v1.7.0/src/ringbuf.c). |
| Static keys / self-modifying code | **Do not transplant the sample into BPF.** It uses the native Linux kernel jump-label API, not an application-controlled BPF instruction-patching facility. Preserve per-lease policy maps. Static keys reduce disabled-path overhead; the example's absolute zero-cycle claim is unjustified. [Kernel static-key API](https://docs.kernel.org/staging/static-keys.html). |
| Computed gotos | **No matching bottleneck identified.** SPLAT is not implementing a C bytecode interpreter in this path. The supplied example has unchecked stream/table indexing and references an undefined `op_drop` label. Prediction quality is workload dependent. Keep bounded Rust/C# parsing; reconsider threaded dispatch only for an actual interpreter with measured dispatch cost. [GCC semantics and bounds warning](https://gcc.gnu.org/onlinedocs/gcc/Labels-as-Values.html). |
| Huge pages | **Do not add `MAP_HUGETLB` to this ring mapping.** SPLAT's ring is 1 MiB, not the hypothetical 1 GiB allocation. BPF ring backing pages are allocated by the kernel and mapped through its map API; changing a userspace mapping flag does not convert them to huge pages. Huge pages can reduce translation pressure for suitable allocations, but do not guarantee that translation stalls disappear. [Kernel allocation and mapping](https://raw.githubusercontent.com/torvalds/linux/master/kernel/bpf/ringbuf.c). |
| BPF tail calls | **Defer until a measured complexity or modularity requirement exists.** A failed tail call falls through, contrary to the attachment. Copying its `return 0` fallback into an LSM enforcement path could permit an operation whose required policy stage never ran. Chains are bounded, targets must be compatible, and the example's kprobe is not an LSM denial hook. Any future design needs a denying fallback for a leased operation that requires the missing stage, plus lifecycle validation of the program array and targets. [Tail-call contract](https://man7.org/linux/man-pages/man7/bpf-helpers.7.html), [current LSM enforcement](C:/C_AGENT_BUILDER/native/splat-agent/src/bpf/lease_lsm.bpf.c:248). |

For the explicit question about pointer casts versus strongly typed spans: **prefer typed, bounded views and owned records; retain raw pointers only inside the native boundary that requires them.** A span or slice can view existing memory without allocating. Its presence does not establish that the underlying pointer, lifetime, alignment, or byte order is valid. The current libbpf record is aligned by the ring protocol; the existing cast is not evidence of an observed alignment failure. If processing moves beyond the callback, copy the small record into owned storage before libbpf advances the consumer. [Current cast](C:/C_AGENT_BUILDER/native/splat-agent/src/main.rs:366), [libbpf callback lifetime](https://raw.githubusercontent.com/libbpf/libbpf/v1.7.0/src/ringbuf.c).

The implementation work I would prioritize is:

1. **Make the binary contract explicit.** Isolate event decoding from the callback. Validate the exact current record length, or an explicitly versioned extension; count malformed records instead of silently discarding them. Add field-offset checks on both sides and byte fixtures covering lengths, endianness, and unknown hook identifiers. Narrow [the generic `bytes_of<T: Copy>` helper](C:/C_AGENT_BUILDER/native/splat-agent/src/lease.rs:135) to explicitly supported layouts or field encoders: `Copy` alone does not establish that a type has no uninitialized padding. A small checked copy can remove alignment assumptions without allocating. [Rust unaligned-read requirements](https://doc.rust-lang.org/std/ptr/fn.read_unaligned.html), [plain-data layout requirements](https://docs.rs/bytemuck/latest/bytemuck/trait.Pod.html).

2. **Make reader initialization failure explicit.** [The current `rb.add` / `rb.build` branches](C:/C_AGENT_BUILDER/native/splat-agent/src/main.rs:365) can skip starting the reader when either operation fails. Propagate that failure into startup readiness when evidence delivery is required, or expose an explicit degraded state. This is a source-confirmed error-handling gap, not a failure reproduced in this review. Verify it with injected registration/build failures; retain the existing interrupted-poll recovery.

3. **Reduce work inside the drain callback if profiling supports it.** It currently allocates formatted strings and logs each denial before broadcasting. Evaluate copying the fixed record to a bounded queue, routing by cgroup, and formatting after routing. Preserve the drain timestamp, kernel timestamp, sequence, and explicit loss accounting. Never retain a borrowed ring pointer in an async task. Stress slow consumers and bursts across concurrent leases; preserve [kernel-versus-forwarded counts and `violationsComplete`](C:/C_AGENT_BUILDER/native/splat-agent/src/main.rs:1743). This is the strongest performance candidate found, not a demonstrated bottleneck.

4. **Measure the actual guest path before changing kernel code.** Separate unleased-hook overhead, allowed leased operations, denial bursts, and full client-to-result latency. Record p50/p95/p99, CPU use, allocations, kernel drops, subscriber lag, and incomplete receipts. Existing [splat-bench](C:/C_AGENT_BUILDER/src/splat-bench/Program.cs:12) measures the Windows launch path. Also, `poll(100 ms)` is a maximum wait passed to `epoll_wait`, not an obligatory 100 ms delay per event; notifications can wake it earlier. Avoid optimizing a latency inferred from that timeout. [libbpf polling](https://raw.githubusercontent.com/libbpf/libbpf/v1.7.0/src/ringbuf.c).

Any BPF source modification also affects deployment: [pin identity includes the source SHA-256](C:/C_AGENT_BUILDER/native/splat-agent/src/pinning.rs:19), and incompatible pin sets refuse startup. Even a seemingly cosmetic C-source change needs the existing drain/migration procedure and renewed applicable enforcement probes. Increasing ring size, adding maps, or splitting programs is therefore more than an isolated memory-layout edit.
